# Дашборд отчётов (колл-центр, карта выдач)

Python-сервер на стандартной библиотеке (`http.server`), единственная зависимость — `pymysql`.
Данные — локальная SQLite `cf.db` (~3 ГБ), раз в минуту догружается из удалённой MariaDB (`sync.py`).

- `server.py` — HTTP-сервер и отчёт «время между статусами» (`/`, `/call-centar`), `/map` — карта выдач.
- `sync.py` — синхронизация `cf.db` с MariaDB; доступ берётся из `.env` (DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME).
- `geo.py`, `regions.py` — данные для карты.
- `import_dump.py` — первичный импорт MySQL-дампа в SQLite (на сервере обычно не нужен: `cf.db` копируется готовой).

## Развёртывание на сервере (Docker)

Сервер: 192.168.1.112, проект в `~/dashboard`.

```
~/dashboard/
  Dockerfile, docker-compose.yml, *.py, *.html, static/
  .env            # доступ к MariaDB, монтируется в контейнер read-only
  data/cf.db      # база, монтируется в /data; если её нет — создаётся и загружается из MariaDB при старте
  data/cf_*.csv   # запасной справочник партнёров (необязательно)
```

Запуск и обновление: `docker compose up -d --build`. Логи: `docker compose logs -f`.
Первый запуск без `data/cf.db` загружает всю таблицу postback_proxy (~9 млн строк, десятки минут);
отчёт открывается после окончания загрузки. Если загрузка прервалась — при следующем запуске она продолжится
в фоне с последнего id.
Отчёт: http://192.168.1.112:8080 (порт привязан только к адресу в локальной сети).

## Важно

- `.env`, `cf.db*`, `cf_*.csv` — не коммитить и не класть в образ (там пароль, персональные данные и данные партнёров).
- В отчёте нет авторизации и есть ФИО/телефоны — не открывать порт наружу (не менять привязку на `0.0.0.0` / `"8080:8000"`).
- Если синхронизация пишет ошибку подключения — проверить, что IP сервера разрешён в MariaDB.
